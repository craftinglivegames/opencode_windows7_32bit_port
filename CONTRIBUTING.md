# Как помочь проекту

Спасибо, что заглянули. Проект хоббийный: неофициальный порт OpenCode на
Windows 7 SP1 x32. Полезнее всего — воспроизводимые баг-репорты с логами и
проверками на реальной Windows 7.

## Куда что писать

| Что | Куда |
|---|---|
| Ошибка в порте, краш, пустой список моделей | issue по шаблону «Проблема с портом» |
| Уязвимость, утечка ключей | [SECURITY.md](SECURITY.md) — приватно, не в issue |
| Баг самого OpenCode, воспроизводимый на Linux/macOS/Win10+ | [upstream](https://github.com/sst/opencode/issues) |
| Вопрос «как собрать/запустить» | `docs/BUILD.md`, `docs/PORT-native-x32.md`, затем issue |

Перед созданием issue проверьте, что пакет распакован целиком, `OpenCode.exe`
разблокирован («Свойства → Разблокировать»), порт 4096 свободен и после
обновления сделан `Ctrl+F5`. Логи — `logs\launcher.log` и `logs\server.log`.

## Pull request

1. Соберите то, что меняете: `docs/BUILD.md` описывает всю цепочку
   (Node + шимы → бандл → лаунчер → архив). Для правок только в документации
   ничего собирать не нужно.
2. Проверьте, что относительные ссылки в markdown живые:
   `python tools/check_links.py` (это же гоняет CI).
3. Бинарники и артефакты в git **не коммитим**: `build/`, `dist/*.exe`,
   `dist/*.zip`, `spike/`, `*.pdb`, `*.obj`, `__pycache__`. Они собираются
   скриптами и едут только в Release. То же для `auth.json`, `opencode.json`
   с настоящими ключами, логов и личных путей (`C:\Users\...`).
4. В коммите — одна законченная правка и понятное сообщение
   (`web UI: ...`, `docs: ...`, `launcher: ...`).

## Стиль

- Русский или английский — как удобнее; документация сейчас в основном
  русская, `README.md` — английский.
- C++ (`src/`) — C++17, MSVC x86, статический CRT, без новых зависимостей без
  необходимости: целевая машина — Atom N2600 и 2 ГБ RAM.
- Python-скрипты (`tools/`) — только стандартная библиотека, Python 3.9+.
- Держите правки совместимыми с Win7: никаких API новее Windows 7 без шима и
  без записи в документации.
